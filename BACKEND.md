# Pixel shared services

The browser interface is served by GitHub Pages. GitHub Pages does not run server code. The account/chat/stats API is a separate Worker backed by a D1 database. The current API connection is declared in api-client.js; it is a service call, not a navigation link.

backend-worker.ts contains a portable Cloudflare Worker implementation of the same tested endpoints. backend-schema.sql contains the schema migrations in order. Bind D1 as DB. Set the FrameX password hash, salt and signing key as runtime secrets using the exact names documented at the top of the Worker; never put their values in this repository. For a new database, apply the SQL once. For an existing database, apply only migrations not already recorded there.

The Worker allows browser calls from the exact owner origin configured by GITHUB_ORIGIN. GitHub clients send X-Pixel-Client: github-pages and authenticate with a one-day bearer token obtained through normal username/password login. Tokens are hashed in the database, kept in tab sessionStorage by the UI and revoked on logout. Cross-origin requests cannot reuse same-origin account cookies. Chat membership and owner permissions are checked on every operation.

Changing the backend host requires deploying this Worker with the database and secrets, and updating the service base URL in api-client.js. Deploying the static repository alone will not create a database. Existing data is not copied into GitHub.

## Administrator and public lobby

Set PIXEL_ADMIN_USERNAME to an existing arcade username to enable its admin access. With the variable absent, admin access is disabled. Admin responses contain account and activity summaries only; no password hashes, salts, passwords or session tokens. The public community lobby is created lazily as product data and every account joins when it opens chat; it is not invite-only and cannot be left. The site_visits migration adds minimal first-party records with a 30-day retention period. The UI starts a new visit when account identity changes, so activity after logout is not attributed to the previous user.

## Social and multiplayer services
`/api/social` provides public profile cards, friend request acceptance, friends-only DM history and blocking. `/api/party` validates two-player Chess, Tic Tac Toe, Connect Four and Dots & Boxes moves with optimistic room versions. `/api/challenges` generates the Sydney-day Lights Out board and replays submitted moves; it never accepts a client-supplied score. `/api/moderation` lets signed-in users report content they can access and restricts report review, timeouts, suspensions and slow mode to the configured administrator. Reports snapshot only the reported item. DMs are not end-to-end encrypted.

The additive `0005` migration introduces social profiles, friendships, blocks, DMs, reports, moderation settings, party rooms and daily scores. Preserve existing accounts, tokens, chat and runtime secrets. The portable Worker imports `backend-chess-engine.js` with its bundled license. Source export is generated by the hosted checkout’s `scripts/export-github-backend.mjs`.

## Password recovery
`POST /api/auth/recovery` supports `setup` (signed in + current password), `change` (current/new password), `reset` (username + recovery code + new password), and `issue` (configured admin + own current password + target username + identity verification acknowledgement). Signup returns a one-time-visible 192-bit backup code. Codes are normalized and SHA-256 hashed; temporary codes expire after 15 minutes. Successful resets atomically update the password with a new salt, revoke every account token, replace the backup code and invalidate all temporary codes. Conditional updates prevent code replay. The additive `0006` migration adds `password_recovery` and code-free `recovery_audit` records. Admin issuance is forbidden for the designated admin account. No emails, secret-bearing URLs or browser-persisted codes are used.
